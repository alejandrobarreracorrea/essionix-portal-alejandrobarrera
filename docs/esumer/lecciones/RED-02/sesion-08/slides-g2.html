📄 main.tf Cada bloque = algo que antes hacías a clics

El código, bloque por bloque

  • provider "aws" { region = "us-east-1" }el traductor a la API de AWS, en Norte de Virginia
  • variable "mi_ip" / "llave"lo que cambia por estudiante: tu IP de casa y tu key pair
  • resource "aws_vpc" "pyme"VPC → Crear VPC → 10.0.0.0/16
  • resource "aws_subnet" "area" (for_each)Subredes → Crear subred ×4 (un solo bloque crea las 4)
  • resource "aws_internet_gateway"Internet gateways → Crear → Asociar a la VPC
  • resource "aws_route_table" + "…_association"Tablas de rutas → 0.0.0.0/0 → IGW → asociar a web
  • resource "aws_security_group" "web"Security Groups → reglas 80 (todos) y 22 (Mi IP)
  • resource "aws_instance" "web" + user_dataLanzar instancia… y NGINX se instala solo al nacer
  • output "tu_web"lo que Terraform te muestra al terminar: tu URL

Fíjense en aws_vpc.pyme.id: así un recurso usa el ID de otro. Por eso Terraform sabe el orden: no puede crear una subred antes que su VPC.

🧪 PASO 0 Crea tu llave para la CLI (en la consola de AWS)

Tu usuario terraform-lab y su access key

  • Barra de búsqueda → IAM → Usuarios → Crear usuarionombre terraform-lab · la casilla de acceso a la consola queda vacía
  • Establecer permisos → Adjuntar políticas directamenteAmazonEC2FullAccess · AmazonSSMReadOnlyAccess · AWSCloudTrail_ReadOnlyAccess
  • Siguiente → Crear usuariolisto tu usuario “robot” (sin AdministratorAccess)
  • Entra a terraform-lab → Credenciales de seguridad → Crear clave de accesocaso de uso CLI · marca “Entiendo…” → Siguiente → Crear clave de acceso
  • Recuperar claves de accesoDescargar archivo .csv: la secreta se ve una sola vez
  • En PowerShell de tu PC (paso 2): aws configurepega el ID y la secreta · región us-east-1 · formato json

Checkpoint ✅ al chat: escribe solo “listo 🔑”. Nunca pegues tu llave en el chat. Al terminar la clase: IAM → terraform-lab → Credenciales de seguridad → Desactivar y Eliminar la clave.

🧪 PASO 1 Prepara tu PC: VS Code, Terraform y la CLI de AWS

Tu PC lista: Terraform + AWS CLI

  • Abre VS Code → menú Terminal → New Terminaluna terminal PowerShell dentro del editor
  • terraform -versionya lo instalaste en la clase 2 ✓
  • aws --versionla CLI de AWS: ¿ya la tienes?
  • winget install -e --id Amazon.AWSCLIsolo si aws no se reconoce · después cierra y abre PowerShell
  • mkdir $HOME\pyme-tf y code $HOME\pyme-tfcrea la carpeta del proyecto y ábrela en VS Code (o File → Open Folder)

Checkpoint ✅ al chat: tu versión de Terraform y de aws-cli. ¿Tienes Mac? Usa la app Terminal y brew install awscli.

🧪 PASO 2 Conecta tu PC a AWS con tu llave

La CLI de AWS: tu cuenta, vista por la API

  • aws configurepega tu llave (ID + secreta) · región us-east-1 · formato json
  • aws sts get-caller-identity"¿quién soy?" → user/terraform-lab
  • aws ec2 describe-vpcs …tus VPC: ¡ahí está la que hiciste a clics!
  • aws cloudtrail lookup-events …busca tu clic: el CreateVpc de la clase pasada
  • aws ec2 describe-key-pairs …anota el nombre de tu key pair

Checkpoint ✅ al chat: user/terraform-lab y el nombre de tu key pair (nunca la llave).

🧪 PASO 3 Toca una pieza del dibujo → copia su bloque → pégalo en main.tf (VS Code)

Arma tu red pieza por pieza con Terraform

Las piezas punteadas aún no existen · al copiar su bloque se “construyen” · el número es el orden

Pega cada bloque una sola vez al final de main.tf · Ctrl+S · terminal: terraform apply → yesreiniciar dibujo
🧪 PASO 4 La magia: correrlo otra vez, cambiar y borrar

El GPS en acción: plan, cambio y destroy

  • terraform plan (otra vez)No changes: ya estás en el destino
  • En main.tf cambia "web-tf" por "web-terraform" · Ctrl+Scambias el nombre de la EC2 en el plano
  • terraform apply1 to change: solo toca lo distinto
  • terraform destroyborra los 10 recursos, en orden inverso

Checkpoint ✅ al chat: Destroy complete! Resources: 10 destroyed. (tu pyme-vpc hecha a clics no se toca)

🏁 RETO Ponle trampas a Terraform

¿De verdad funciona como un GPS?

  • 1 · Antes del destroy, en la consola borra a mano la ruta 0.0.0.0/0 de rt-publica-tf… y corre terraform plan. ¿Qué te dice?
  • 2 · Agrega en el plano una quinta subred "wifi" = "10.0.1.128/28" y corre terraform plan: ¿cuántos recursos agrega?
  • 3 · Sube tu main.tf a tu repositorio de GitHub (¡nunca el terraform.tfstate ni tu .ppk!)

Pista del 1: Terraform detecta que la realidad ya no coincide con el plano y la vuelve a crear. A eso se le llama drift (deriva).

✅ CIERRE Deja la casa en orden

Antes de irte: cero recursos sueltos

  • terraform destroy → 10 destroyed (en la consola ya no aparece pyme-vpc-tf)
  • Tu pyme-vpc hecha a clics y tu EC2 de siempre siguen intactas (Terraform solo toca lo que él creó)
  • La carpeta C:\Users\tú\pyme-tf queda en tu PC: la próxima clase solo haces terraform apply
  • Tu llave: IAM → terraform-lab → Credenciales de seguridad → Desactivar y Eliminar (y en PowerShell: Remove-Item $HOME\.aws\credentials)
  • El terraform.tfstate, la .ppk y el .csv de la llave nunca van a GitHub
  • ¿No vas a usar tu EC2 de siempre hoy? Stop — capa gratuita cuidada 💵
