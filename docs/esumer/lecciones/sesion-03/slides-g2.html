PARTE 1 · LINUX Repaso — vuelve a encender tu servidor

Enciende tu máquina Linux en la nube

  • 1 · Consola AWS → busca EC2 → arriba a la derecha elige región N. Virginia (us-east-1)
  • 2 · Launch instance → nombre: mi-primer-servidor
  • 3 · Imagen: Amazon Linux (Free tier eligible) · Tipo: t2.micro o t3.micro (Free tier) 🟢
  • 4 · Key pair: Create new key pair → tipo .pem → descárgala (es tu llave — no la pierdas)
  • 5 · Network settings: ✓ Allow SSH from Anywhere · Launch instance

La clase pasada ya lo hicieron — hoy es repaso. Si la terminaste, créala otra vez (es rapidísimo); si la dejaste en Stop, solo pon Start. Costo: $0 en capa gratuita.

PARTE 1 · LINUX Reconéctate a tu servidor por SSH

Conéctate a tu servidor con SSH

  • 1 · EC2 → Instances → espera a Running ✅ y copia su IP pública
  • 2 · En tu terminal, donde está tu llave: chmod 400 tu-llave.pem
  • 3 · ssh -i tu-llave.pem ec2-user@<IP-pública> → responde yes → entras: ec2-user@ip-...:~$
🐧

Esto SÍ es Linux 100% real (Amazon Linux) — el kernel, los paquetes, todo. La terminal manejando el sistema operativo.

Checkpoint: ✅ al chat cuando veas ec2-user@...$ · ¿No conecta? suele ser la llave (permisos) o el puerto 22 del security group — lo resolvemos en el momento.

PARTE 1 · LINUX · lab 1 Ubícate y conoce tu servidor

¿Quién soy, dónde estoy… y qué máquina es esta?

$ whoami     # ¿quién soy aquí? → ec2-user

$ hostname   # ¿cómo se llama este servidor?

$ pwd       # ¿en qué carpeta estoy?

$ uname -a   # ¿qué sistema es? (Linux 👀)

$ uptime    # ¿hace cuánto está encendido?

$ df -h     # ¿cuánto disco tengo?

$ free -h   # ¿cuánta memoria RAM?

$ nproc     # ¿cuántos procesadores?

Acaban de leerle las specs a un servidor real en Virginia. Al chat: ¿cuántos GB de disco te dio df -h?

PARTE 1 · LINUX · lab 2 Construye la estructura de tu proyecto

Carpetas, archivos y redirección

$ mkdir -p mi-empresa/{web,datos,logs}  # 3 carpetas de un golpe

$ cd mi-empresa && ls -R     # míralas en árbol

$ echo "Bienvenido a mi empresa" > web/index.html  # crea (>)

$ echo "nombre,ciudad" > datos/clientes.csv

$ echo "Ana,Medellín" >> datos/clientes.csv  # AÑADE (>>)

$ echo "Luis,Bogotá" >> datos/clientes.csv

$ cat datos/clientes.csv   # léelo completo

$ ls -lh datos/      # tamaño legible para humanos

> crea y pisa el archivo · >> añade sin borrar · {a,b,c} (brace expansion) te ahorra media vida.

PARTE 1 · LINUX · lab 3 Copiar, mover y borrar (con cuidado)

Las tijeras de Linux

$ cp datos/clientes.csv datos/backup.csv  # copiar

$ mv datos/backup.csv datos/clientes-2024.csv # renombrar/mover

$ ls datos/

$ rm datos/clientes-2024.csv   # borrar archivo — SIN papelera ⚠️

$ rm -r logs/         # borrar carpeta entera ⚠️⚠️

rm no perdona — no hay papelera. Respirar, leer dos veces, y solo entonces borrar. rm -rf / es la pesadilla de todo sysadmin: nunca lo escriban.

PARTE 1 · LINUX · lab 4 Explora, filtra… y sé el administrador

Buscar, tuberías, e instalar software

$ wc -l datos/clientes.csv   # ¿cuántas líneas?

$ grep "Medellín" datos/*.csv # busca DENTRO de los archivos

$ find . -name "*.html"     # busca archivos por nombre

$ cat datos/clientes.csv | sort # tubería | : conecta comandos

$ history | tail -5      # tus últimos comandos

$ sudo yum install -y tree  # instala software (root con sudo)

$ tree mi-empresa      # tu proyecto en árbol bonito 🌳

Buscaste, filtraste con tuberías e instalaste software en un servidor real. Eso es administrar infraestructura. Cerramos el repaso — ahora lo guardamos en internet.

PARTE 2 · GITHUB Cambio de escenario

Tu trabajo vive solo en el server. Vamos a guardarlo en internet

📐

Git es el archivo del arquitecto: guarda cada versión de tu trabajo. GitHub es la oficina en internet donde ese archivo vive y lo puede ver el mundo. Así trabaja todo equipo de tecnología del planeta.

  • Esto lo hacemos en tu propia máquina (donde instalaste Git la clase 2):
  • 🪟 Windows: abre Git Bash  ·  🍎 macOS: abre la Terminal

De aquí en adelante, los comandos son en TU terminal local.

PARTE 2 · GITHUB Paso 1 — crea tu repositorio

Tu casillero en internet, en github.com

  • 1 · Entra a github.com e inicia sesión (si no tienes cuenta, créala — es gratis)
  • 2 · Arriba a la derecha: + → New repository
  • 3 · Nombre: bitacora-tu-empresa · visibilidad Public
  • 4 · Create repository → copia la URL que te muestra (…​.git)

Un repositorio es una carpeta con memoria: guarda tu trabajo y todas sus versiones. Aún está vacío — ya lo llenamos desde tu terminal.

PARTE 2 · GITHUB Paso 2 — prepara y firma tu trabajo

git config + init + commit

$ git config --global user.name "Tu Nombre"

$ git config --global user.email "tu@correo.com" # el MISMO de GitHub

$ mkdir bitacora-tu-empresa && cd bitacora-tu-empresa

$ echo "Aprendí Linux y GitHub" > cheat-sheet.md

$ git init        # crea el archivo del arquitecto (.git)

$ git add .       # "arquitecto: mira esto"

$ git commit -m "Mi primer ejercicio" # fírmalo en el plano

La carpeta oculta .git ES el archivo del arquitecto — por eso Git solo ve lo que pasa dentro de esta carpeta.

EL RITO DE PASO Paso 3 — tu primer push

De tu máquina al mundo

$ git remote add origin <URL-que-copiaste> # conecta con tu repo

$ git branch -M main

$ git push -u origin main     # "archívalo en la oficina"

🌐

La primera vez, se abre el navegador para iniciar sesión en GitHub — una sola vez y queda guardado. Sin token.

Recarga github.com/tu-usuario/bitacora-tu-empresa… ahí está cheat-sheet.md, publicado. Editar local → push al mundo: ya son parte del flujo del planeta. 📐

Parte 3 · Networking · abrimos las calles

De los cimientos a las calles

🗺

Ya repasaste tu casa (Linux) y la publicaste en internet (GitHub). Pero una casa sola no sirve de nada si nadie puede llegar a ella. Ahora abrimos las calles y la dirección: las redes.

Redes = cómo las casas se encuentran y se hablan entre sí. Es el módulo que le da el nombre al curso.

Networking · idea 1

¿Qué es una red?

  • 🏠 Una red local (LAN) — las casas de un mismo barrio: tu router, tu compu y tu celular hablando entre sí
  • 🌆 Internet — todos los barrios del mundo conectados: una red de redes
  • 📦 Los mensajes viajan en paquetes, como cartas con remitente y destinatario

Sin redes, tu servidor es una casa hermosa en medio de la nada. Con redes, el mundo puede tocar a la puerta.

Networking · idea 2

La dirección de tu casa: la IP

  • Cada casa en internet tiene una dirección única para recibir visitas: su dirección IP
  • 192.168.0.10 — privada (dentro de tu barrio) · 3.220.15.4 — pública (hacia el mundo)
  • Tu EC2 de hoy tenía una IP pública — por eso pudiste conectarte a ella

# ¿cuál es la dirección de esta casa?

$ ip addr   # (o ifconfig)

$ curl ifconfig.me # tu IP pública

Networking · idea 3

¿Cómo llega un mensaje? TCP/IP

📮

TCP/IP es el servicio de mensajería de internet: parte tu mensaje en paquetes, les pone la dirección (IP), los manda por las calles y los vuelve a armar al llegar — y si uno se pierde, lo reenvía.

  • IP — la dirección: a qué casa va el mensaje
  • TCP — el mensajero cuidadoso: que llegue todo, completo y en orden

La próxima clase: cómo se reparten esas direcciones (IPv4, redes privadas) y los servicios que lo hacen funcionar (DNS, DHCP).
