ACTIVIDAD Tu primer servidor Linux — de verdad

Lancemos una máquina Linux en la nube

  • 1 · Consola AWS → busca EC2 → arriba a la derecha elige región N. Virginia (us-east-1)
  • 2 · Launch instance → nombre: mi-primer-servidor
  • 3 · Imagen: Ubuntu (Free tier eligible) · Tipo: t2.micro o t3.micro (Free tier) 🟢
  • 4 · Key pair: Proceed without a key pair (entraremos por el navegador)
  • 5 · Network settings: ✓ Allow SSH from Anywhere · Launch instance

Acaban de pedir un computador Linux completo, encendiéndose en un datacenter de Virginia. Costo: $0 en capa gratuita — hoy lo apagamos al terminar.

ACTIVIDAD Entra a tu servidor — sin llaves, sin líos

EC2 Instance Connect: Linux en tu navegador

  • 1 · EC2 → Instances → espera a que diga Running ✅ (~1 min)
  • 2 · Selecciona tu instancia → botón Connect → pestaña EC2 Instance Connect → Connect
  • 3 · Se abre una terminal negra en el navegador con: ubuntu@ip-...:~$
🐧

Esto SÍ es Linux 100% real — el kernel, los paquetes, todo. Aquí sí se cumple lo que vimos: la terminal manejando el sistema operativo.

Checkpoint: ✅ al chat cuando veas ubuntu@...$ · ¿Sin cuenta AWS o sin tarjeta? → killercoda.com (Ubuntu en el navegador, gratis) y sigues todos los labs igual.

LAB 1 Ubicarse — dentro de TU servidor Linux

¿Dónde estoy? ¿Qué hay aquí?

$ whoami   # ¿quién soy en este servidor?

$ pwd      # ¿en qué carpeta estoy?

$ ls -la  # ¿qué hay aquí, incluso lo oculto?

$ uname -a # ¿qué sistema es este? (Linux 👀)

$ cd / && ls # la raíz del sistema — el mapa de Linux

$ cd ~      # volver a casa · clear para limpiar

Mini-reto al chat: ¿qué te respondió whoami? (todos serán ubuntu — están dentro del servidor, no en su PC)

LAB 2 Construir

Las primeras piezas, en tu propia máquina

$ mkdir curso && cd curso

$ echo "Somos [tu empresa]" > lema.txt

$ cat lema.txt

$ cp lema.txt lema-v2.txt   # copiar

$ mv lema-v2.txt slogan.txt # renombrar

$ rm slogan.txt         # borrar — SIN papelera ⚠️

rm no perdona. Respirar, leer dos veces, y solo entonces borrar.

LAB 3 Conectar el servidor con la oficina de planos

git config + traer tus planos

$ git config --global user.name "Tu Nombre"

$ git config --global user.email "tu@correo.com"  # el MISMO de GitHub

$ git clone https://github.com/TU-USUARIO/bitacora-tu-empresa.git

$ cd bitacora-* && ls -la    # el README… y la carpeta .git 👀

Clonar un repo público no pide clave (es solo leer). La carpeta oculta .git ES el archivo del arquitecto — por eso Git solo ve lo que pasa dentro de esta carpeta.
Para SUBIR (push) desde el servidor sí pedirá clave: ahí va tu token de GitHub (lo creamos en 1 minuto — ver chat).

EL RITO DE PASO tu primer push

De tu máquina al mundo — en 3 comandos

$ mkdir planos materiales && echo "Somos [empresa]" > materiales/lema.txt

$ git add .                     # "arquitecto: mira esto"

$ git commit -m "Primeras piezas de la casa" # "fírmalo en el plano"

$ git push                      # "archívalo en la oficina"

  • Abran github.com/[usuario]/bitacora-[empresa]… ahí están sus carpetas, publicadas

Editar local → push al mundo: el flujo de los equipos de tecnología del planeta. Ya son parte. 📐

⚠️ Paso NO negociable · antes de cerrar

Apaga tu servidor — o te sigue corriendo el taxímetro

  • 1 · Consola AWS → EC2 → Instances → selecciona tu instancia
  • 2 · Botón Instance state → elige:
  •    🅰️ Stop — la apagas para seguir usándola después (queda guardada, no cobra cómputo)
  •    🅱️ Terminate — la borras por completo (hoy, como fue de práctica, esta es la segura)
  • 3 · Verifica que quede en Stopped o Terminated ✅

Un servidor encendido que nadie usa gasta. Apagar lo que no se usa es la regla de oro de operar en la nube — y la vamos a repetir todo el semestre. Todos apagamos ahora, juntos.

🔐 Minuto de seguridad #1 · nueva tradición

Tres reglas que cuidan tu casa (y tu bolsillo)

  • La clave ROOT de AWS es sagradaPuede TODO: gastar, borrar, regalar el terreno. Larga, en un gestor, JAMÁS compartida — ni "un momentico"01
  • Un repo público es una casa con ventanasJamás subir contraseñas, llaves, tokens ni datos personales — hay bots escaneando GitHub 24/702
