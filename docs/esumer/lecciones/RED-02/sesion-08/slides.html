📄 main.tf Cada bloque = algo que antes hacías a clics

El código, bloque por bloque

  • provider "aws" { region = "us-east-1" }el traductor a la API de AWS, en Norte de Virginia
  • variable "mi_ip" / "llave"lo que cambia por estudiante: tu IP de casa y tu key pair
  • resource "aws_vpc" "pyme"VPC → Crear VPC → 10.0.0.0/16
  • resource "aws_subnet" "area" (for_each)Subredes → Crear subred ×4 (un solo bloque crea las 4)
  • resource "aws_internet_gateway"Internet gateways → Crear → Asociar a la VPC
  • resource "aws_route_table" + "…_association"Tablas de rutas → 0.0.0.0/0 → IGW → asociar a web
  • resource "aws_security_group" "web"Security Groups → reglas 80 (todos) y 22 (Mi IP)
  • resource "aws_instance" "web" + user_dataLanzar instancia… y NGINX se instala solo al nacer
  • output "tu_web"lo que Terraform te muestra al terminar: tu URL

Fíjense en aws_vpc.pyme.id: así un recurso usa el ID de otro. Por eso Terraform sabe el orden: no puede crear una subred antes que su VPC.

🧪 PASO 1 Abre CloudShell y habla con la API

La CLI de AWS: tu cuenta, vista por la API

  • En la consola de AWS, ícono >_ (arriba a la derecha)abre CloudShell: una terminal con tus credenciales
  • aws sts get-caller-identity"¿quién soy?" para la API
  • aws ec2 describe-vpcs …tus VPC: ¡ahí está la que hiciste a clics!
  • aws cloudtrail lookup-events …busca tu clic: el CreateVpc de la clase pasada
  • aws ec2 describe-key-pairs …anota el nombre de tu key pair

Checkpoint ✅ al chat: el nombre de tu key pair. Revisa arriba a la derecha que la región sea N. Virginia (us-east-1).

🧪 PASO 2 Instala Terraform y baja el plano

Terraform en CloudShell

  • curl … terraform_1.16.5_linux_amd64.zipdescarga Terraform (un solo archivo)
  • unzip … -d ~/binlo deja en tu carpeta personal
  • terraform -version¿quedó instalado?
  • curl -sO …/main.tfbaja el plano de la clase
  • cat main.tfléelo: cada bloque es algo que antes hacías a clics

Los comandos completos te los paso por el chat (para copiar y pegar). Checkpoint ✅: Terraform v1.16.5.

🧪 PASO 3 init y plan: el presupuesto antes de la obra

¿Qué va a construir? terraform plan

  • En tu navegador abre checkip.amazonaws.comesa es tu IP de casa (para el SSH)
  • terraform.tfvarstus datos: IP con /32 y nombre de tu key pair
  • terraform initdescarga el provider (el traductor)

🧪 PASO 4 apply: que se construya la obra

Un comando, 10 recursos

  • terraform applymuestra el plan otra vez y pregunta
  • yes"sí, constrúyelo"
  • Mira el ordenVPC primero, después subredes… Terraform lo calcula solo
  • tu_web = "http://…"espera 1–2 min (NGINX se instala) y ábrela
  • Consola → VPCahí está pyme-vpc-tf, igualita a la tuya

Checkpoint ✅ al chat: pantallazo de tu página “Hola desde Terraform 🚀”.

🧪 PASO 5 La magia: correrlo otra vez, cambiar y borrar

El GPS en acción: plan, cambio y destroy

  • terraform plan (otra vez)No changes: ya estás en el destino
  • sed -i … main.tfcambias el nombre de la EC2 en el plano
  • terraform apply1 to change: solo toca lo distinto
  • terraform destroyborra los 10 recursos, en orden inverso

Checkpoint ✅ al chat: Destroy complete! Resources: 10 destroyed. (tu pyme-vpc hecha a clics no se toca)

¿Entonces los clics no sirven? Sí: para aprender y explorar. Para construir y mantener, el código. Por eso primero lo hicieron a mano: ahora entienden cada línea del plano. 🧠

🏁 RETO Ponle trampas a Terraform

¿De verdad funciona como un GPS?

  • 1 · Antes del destroy, en la consola borra a mano la ruta 0.0.0.0/0 de rt-publica-tf… y corre terraform plan. ¿Qué te dice?
  • 2 · Agrega en el plano una quinta subred "wifi" = "10.0.1.128/28" y corre terraform plan: ¿cuántos recursos agrega?
  • 3 · Sube tu main.tf a tu repositorio de GitHub (¡nunca el terraform.tfstate ni tu .ppk!)

Pista del 1: Terraform detecta que la realidad ya no coincide con el plano y la vuelve a crear. A eso se le llama drift (deriva).

✅ CIERRE Deja la casa en orden

Antes de irte: cero recursos sueltos

  • terraform destroy → 10 destroyed (en la consola ya no aparece pyme-vpc-tf)
  • Tu pyme-vpc hecha a clics y tu EC2 de siempre siguen intactas (Terraform solo toca lo que él creó)
  • La carpeta ~/pyme-tf queda guardada en CloudShell: la próxima clase solo haces terraform apply
  • El terraform.tfstate y la .ppk nunca van a GitHub
  • ¿No vas a usar tu EC2 de siempre hoy? Stop — capa gratuita cuidada 💵
