De tu casa al mundo: LAN, WAN e Internet

🏠LANRed local — tu casa u oficina: router, PC y celular hablando entre sí
🏙️MANRed metropolitana — una ciudad o un campus conectado
🌍WANRed amplia — ciudades y países enlazados a larga distancia

📦PaquetesTodo viaja partido en paquetes, como cartas con remitente y destino
🎯Misma idea, distinta escalaEntiendes una red pequeña y entiendes internet
PARTE 2 · TEORÍA ¿Cómo se ponen de acuerdo dos máquinas?

El modelo OSI: 7 capas, cada una con su oficio

7Aplicaciónweb, correo · HTTP, DNS
6Presentaciónformato y cifrado · TLS
5Sesiónabre y mantiene la charla
4Transportecompleto y en orden · TCP/UDP
3Redla ruta por la dirección · IP
2Enlaceal equipo vecino · MAC
1Físicacable, fibra, wifi · bits

Cada capa hace UN trabajo y le pasa a la siguiente — como una mensajería donde cada área sabe lo suyo. TCP/IP (lo que ya vieron) es la versión práctica de esto.

PARTE 2 · TEORÍA La dirección, a fondo

Direcciones IPv4: pública, privada y puertos

  • IPv4 = 4 números de 0 a 255: 3.220.15.4
  • Privada (dentro de tu barrio): 192.168.x.x · 10.x.x.x — no se ve desde internet
  • Pública: única en el mundo, la que da la cara (tu EC2 tiene una)
  • Máscara (/24): dice qué parte es el barrio y qué parte la casa
  • Puerto: la puerta del servicio — 22 SSH · 80 HTTP · 443 HTTPS
🏘️

IP = la dirección del edificio. Puerto = el número del apartamento. Juntos llevan el mensaje a la puerta exacta.

PARTE 2 · TEORÍA Los servicios que hacen la magia invisible

DNS, DHCP y NAT

📖DNSLa agenda de internet: traduce google.com → su IP. Nadie memoriza números
🎫DHCPEl repartidor: al conectarte, te asigna una IP automáticamente
🚪NATEl portero del barrio: deja que muchas IP privadas salgan al mundo por una pública

Los tres trabajan callados en cada conexión que hacen — hasta en el wifi de su casa.

PARTE 2 · LAB Ver la red con tus propios ojos

Herramientas de diagnóstico — en tu EC2

$ ping google.com    # ¿llega? ¿cuánto tarda? (Ctrl+C para parar)

$ curl ifconfig.me    # ¿cuál es mi IP pública?

$ nslookup google.com # el DNS en acción: nombre → IP

$ tracepath google.com # el camino, salto por salto

$ ss -tuln        # ¿qué puertos tengo abiertos?

PARTE 3 · AWS Las mismas ideas… en la nube

Todo esto ya existe en AWS

☁️

Lo que acaban de ver (redes, IP, puertos, firewalls) no cambia en la nube: AWS solo le pone nombre y botones. Conocen la teoría → van a reconocer las piezas al instante.

  • Su barrio privado → la VPC
  • Las cerraduras y puertos → los Security Groups
  • El recepcionista que reparte visitas → el Load Balancer
PARTE 3 · AWS Tu barrio privado en la nube

La VPC — Virtual Private Cloud

  • Una red privada tuya dentro de AWS, con su propio rango de IPs
  • Subred pública: da a la calle (internet) — ahí va lo que el mundo debe ver
  • Subred privada: sin salida directa — bases de datos, cosas sensibles
  • Tu EC2 vive dentro de una subred de tu VPC
🏘️

La VPC es tu urbanización cerrada: tú decides las calles (subredes) y quién entra por dónde. Nadie más comparte tu red.

Un túnel VPN te deja entrar a ese barrio privado de forma segura desde afuera — como una puerta lateral cifrada.

PARTE 3 · AWS Las cerraduras de tu servidor

Security Groups: el firewall de tu EC2

  • Un firewall que decide qué puertos están abiertos y para quién
  • Por defecto: todo cerrado. Tú abres solo lo necesario, regla por regla
  • Ej.: 22 (SSH) solo para TU IP · 80/443 (web) para todo el mundo
  • Cuando lanzaron la EC2 y marcaron "Allow SSH from Anywhere" → eso era un Security Group

Cada puerto abierto es una puerta. Menos puertas = menos formas de entrar sin permiso. 🔐

PARTE 3 · AWS Cuando un servidor no alcanza

El balanceador de carga

🛎️

Es el recepcionista de un edificio con muchas taquillas: recibe a todas las visitas y las reparte entre varios servidores para que ninguno colapse.

  • Reparte el tráfico entre varias EC2 → aguanta muchos más usuarios
  • Si un servidor se cae, manda las visitas a los que siguen vivos (alta disponibilidad)
  • En AWS: Elastic Load Balancer (ELB / ALB)

Así funcionan Netflix, los bancos, todo lo que no se puede caer: nunca un solo servidor solo.

PARTE 4 · SEGURIDAD Cambio de sombrero

Ahora, blindemos tu servidor

🛡️

Un servidor abierto al mundo es una casa con puertas: hay que ponerles cerradura. Empezamos a perfilar tu EC2 para que sea más seguro — el primer paso del módulo de ciberseguridad.

Regla de oro: abre lo mínimo, cierra todo lo demás.

PARTE 4 · SEGURIDAD Paso 1 — cierra puertas

Afina el Security Group de tu EC2

  • 1 · Consola AWS → EC2 → tu instancia → pestaña Security → el security group
  • 2 · Edit inbound rules
  • 3 · SSH (22): cámbialo de "Anywhere" a My IP — solo tú entras por SSH
  • 4 · Deja abierto al mundo solo lo que sirva a los visitantes (80/443 si publicas web)
  • 5 · Borra cualquier regla que no reconozcas o no uses

"SSH abierto a todo internet" es la puerta #1 que golpean los bots. Ciérrenla hoy. 🔒

PARTE 4 · SEGURIDAD Paso 2 — endurece el servidor

Cuatro hábitos que te cuidan (y te ahorran sustos)

  • 🔑 Tu llave .pem es sagrada — no la subas a GitHub ni la compartas
  • 🔄 Actualiza el sistema: parches de seguridad al día
  • 👤 No trabajes como root — usa tu usuario y sudo solo cuando toca
  • 🚪 Menos es más: menos puertos y programas = menor superficie de ataque

# mantén tu servidor al día

$ sudo yum update -y

# ¿quién escucha en el puerto 22?

$ sudo ss -tuln | grep :22
